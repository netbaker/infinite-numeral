## 1. 系统概述

数字人格是**跨 Run 的元升级层**，将玩家在档案馆中积累的历史统计「印记」凝练为一种**身份身份加成**。它不提供堆乘数式的通胀通道，而是依据玩家真实玩法风格（维度广度 / 熵控能力 / 编年深度）派生一类**有界、饱和、凹性**的加成，并在 L2 提供**机制/质量**型增益。设计支柱「印记优先于通胀」的核心载体。

玩家从 3 个原型中选择 1 个**激活人格**，用稀缺元货币 `数字印记` 升至 L1 / L2（MVP 仅 1~2 档）。数字印记来源仅 = 里程碑超越(5/10/25/50/100) + 9 个档案特殊成就首解 → 全周期上限 14 枚（见 §2.3），天然稀缺、非生产挂钩。

## 2. 核心机制

### 2.1 三个原型（由历史统计派生推荐，但可自由选）

| 原型 ID | 名称 | 主导历史统计（s 向量） | 风格画像 |
|---------|------|------------------------|----------|
| `persona_walker` | 维度行者 | 访问过的维度种类数 / 维度精通度 | 广域探索者 |
| `persona_tamer` | 熵之驯者 | 单位 Run 熵崩率↓ / 存活最高熵 | 稳健控制者 |
| `persona_chronicler` | 编年史家 | 事件触发总数 / 总 Run 数 / 总超越数 | 叙事收集者 |

推荐逻辑：比较三类归一化深度，高者推荐，但玩家可无视推荐自由选（保持「每个 Run 都独一无二」的自主选择）。

### 2.2 等级与货币

- 等级：`L0`（未选/未激活）→ `L1` → `L2`（MVP 封顶 L2）。
- 货币 `数字印记 (numeralImprints)`：`number`，存于 `GameState`（随主存档序列化，已是扁平标量，无 ADR-002 问题）。
- 成本（可调）：`L1 = 3 印记`，`L2 = 8 印记`。
- 来源（**有界，全周期 ≤ 14 枚**）：
  - 里程碑超越：第 5/10/25/50/100 次 Transcend 各 +1（=5）
  - 档案特殊成就：9 个 `group:'archive'` 成就首次解锁各 +1（=9）

### 2.3 加成公式（核心）

设历史归一化统计向量 **s = (s₁…sₙ)**，每分量 ∈ [0,1]（由档案馆 `ArchiveSummary` / 全量快照聚合得到，与 Run 次数无关，仅与「质量」有关）。

```
A(s)  = Σ_i w_i · s_i                              // 历史深度指数，无量纲，∈[0,1]
D(s)  = D_max · (1 − e^(−k · A(s)))                // 饱和凹性加成率，无量纲，∈[0, D_max]
effMult = M_run · (1 + D(s))                        // 最终乘区；M_run = 既有飞升/超越/基因乘区
L2 机制加成 g: 见 §2.4（非乘区，独立于 effMult）
```

参数建议：`D_max = 0.25`（加成率上限 +25%）、`k = 2.0`、`Σw_i = 1`。

> **关键**：`D(s)` 是 `A(s)` 的**凹函数（边际递减）且全局有界**（≤0.25）。它**加入对数乘区**（即 `1+D` 乘到 `M_run`），但其值**不随游玩时长/超越次数增长**——只随「历史质量深度」饱和收敛。

### 2.4 L2 机制加成（非乘区，杜绝纯线性通胀）

| 原型 | L2 机制加成 g（不计入 `effMult`） |
|------|----------------------------------|
| 维度行者 | 进入新维度首次切换**免冷却**（维度切换冷却减半/免） |
| 熵之驯者 | 熵崩损失上限封顶 **50%**（原本可能清零更多产出） |
| 编年史家 | 每轮开局获得基于历史深度的**一次性起始缓冲**（一次性 stardust/数字 boost，非永久乘区） |

L2 **不提供额外 `D` 倍率**，仅改变机制/质量 → 不增加生产指数。

## 3. 数据结构（新增）

```typescript
// types/game.ts 新增
export type PersonaId = 'persona_walker' | 'persona_tamer' | 'persona_chronicler';

export interface PersonaState {
  active: PersonaId | null;                  // 当前激活人格（仅 1 个）
  levels: Record<PersonaId, 0 | 1 | 2>;      // 各人格独立等级（per-persona map）
}
// 注：levels 为各人格独立等级映射，切换激活人格时旧人格等级保留（见 §6 边缘情况 #5）。
// GameState 新增字段：
numeralImprints: number;        // 数字印记（元货币）
persona: PersonaState;          // 数字人格状态
```

`numeralImprints` 为标量，`persona` 为轻量对象 → `Serializer` 直接扁平序列化（无需 ADR-002 独立表）。

## 6. 边缘情况

1. **旧存档无 `persona` / `numeralImprints`**：`Serializer` 反序列化 `??` 兜底为 `{active:null, level:0}` / `0`；面板显示「未激活」。
2. **印记来源重复计数**：里程碑超越与成就首解均用幂等 Set（已存在的 transcendCount 里程碑 / 已解锁成就）防重发。
3. **同时达多个里程碑超越（离线大跳）**：循环补发印记，但每个里程碑只发一次（幂等）。
4. **L2 机制与既有系统冲突**：驯者封顶 50% 须 `min(loss, 0.5·production)`；不与 EntropySystem 其他减损叠加为负。
5. **切换激活人格**：已升级的 L1/L2 保留在旧人格；切换后新人格从 L0 起（印记不退还，谨慎切换提示）。

## 7. 验收标准

1. `numeralImprints` 仅在里程碑超越(5/10/25/50/100)与 9 个 archive 成就首解时 +1，全周期 ≤ 14。
2. 激活人格 + `D(s)` 加成正确并入 `effMult`，且 `D(s) ≤ 0.25`。
3. L1/L2 升级消耗正确印记，不足时禁用。
4. L2 机制加成（免冷却 / 损失封顶 / 起始缓冲）正确生效且不影响其他系统。
5. 旧存档加载不崩，`persona` 默认未激活。
6. UI 推荐徽章与印记计数正确。

### 7.5 非纯线性通胀证明（设计红线自检）

| 维度 | 纯线性通胀模型（禁止） | 本模型 |
|------|----------------------|--------|
| 形式 | `effMult = M_run · (1 + c·L)` | `effMult = M_run · (1 + D(s))`，`D(s)=D_max(1−e^(−kA))` |
| 有界性 | 随 L 无界增长 → **纯线性通胀** | `D(s) ≤ D_max = 0.25`，**全局有界**，不随时长增长 |
| 边际性 | 每级固定 +c（线性） | `D` 对 A **凹**（边际递减）：A:0→0.5 增 0.158，A:1→2 仅增 0.028（k=2 示例） |
| L2 贡献 | 额外乘区（叠层乘数→主导策略） | **机制/质量**加成，不进 `effMult`，不增生产指数 |
| 主导策略 | 「叠人格等级刷乘数」 | 不可行（等级封顶 L2、加成有界）→ 玩家转向**效率/一致性** |

**数值示例**（k=2, D_max=0.25）：A=0 → D=0；A=0.5 → 0.158；A=1 → 0.216；A=2 → 0.244。
- 由 A=1 增至 A=2（历史深度翻倍），加成仅 +0.028（<2%），**显著次线性** → 非纯线性通胀。
- 无论游玩多久，加成永不超 25% → **不通胀**。✅ 满足支柱①与设计红线。
