## 2. 方向 A：档案馆与数字人格 meta（推荐）

### 2.1 一句话定位与核心动词
**定位**：将每次 Transcend 自动沉淀为"运行快照"，积累成玩家的数字文明档案馆，并据此解锁基于历史统计的"数字人格"永久身份加成——让 meta 进度由"你玩过怎样的宇宙"驱动，而非"数字多大"。
**核心动词**：**铭刻（Inscribe） / 见证（Witness）**。

### 2.2 已上线的档案数据链路（Sprint 5 在其上拓展，不重复造轮子）

> **GDD rev.2 权威口径（已对齐）**：档案馆快照层已 **COMPLETE / ONLINE**——`captureRun` → `persistArchiveRecord` → Dexie `archives` 表全链路已 wired 且 live，`ArchiveRecord` 接口与 `captureRun` 返回字段一致，无缺失字段。

```
每次 Transcend（已在运行）
  → `captureRun` 采集本轮快照（复用 TranscendSystem 重置前数据 + EventSystem 计数 + 基因快照 + 维度数据）
  → `persistArchiveRecord` 写入 Dexie `archives` 表（ADR-002，独立表，已 live）
  → 触发 `evaluateSpecialAchievements`（`gameStore.ts:1095`，依赖的快照现已落库 → 已正常触发）
  → 累计档案统计 → 支撑"数字人格"元升级（基于 Run 多样性 / 历史最高 log10 / 最快 Run，非线性倍率）
  → 玩家打开 `ArchiveModal` 对比历史 Run、查看身份成长
```

- **零重复造轮子**：`archiveUnlocked` 标志、`captureRun`/`persistArchiveRecord`、`evaluateSpecialAchievements`、`computeSummary`、特殊成就定义（9 个，见 `src/core/Constants.ts:730-829`，`group:'archive'`）、`GeneSnapshot` 类型、**Dexie `archives` 表**均已存在且在线；Sprint 5 只需在已 live 的快照层之上加"数字人格元升级 / Run 对比 / 档案分享"等拓展层，无需重建底层。

### 2.3 关键系统拆解（6 个子系统）
1. **快照采集与持久化（已在线 · 基线）**：`captureRun` → `persistArchiveRecord` 写入 Dexie `archives` 表全链路已 wired 且 live（ADR-002，独立表），Sprint 5 **无需重建**；本方向的实际 Must 是下方"数字人格元升级层"等拓展。**基线已具备**。
2. **档案馆 UI（ArchiveModal）**：快照卡片网格 + 统计总览 + 筛选排序 + 详情/对比视图（设计见 `design/gdd/archive-system.md` §5）。**Must**。
3. **数字人格元升级层**：基于档案统计的永久身份加成（如"历史最高 log10≥X"解锁身份档位，提供少量全局倍率/特殊叙事），**非纯线性通胀**。**Must（核心闭环）**。

> **权威口径（R1 已拍板）— 数字印记与量级里程碑脱钩**：数字人格的元货币 `数字印记` 来源硬上限 = **14 枚** = 5 次里程碑超越（第 5/10/25/50/100 次 Transcend）+ 9 个档案成就首解；量级里程碑**仅发放非货币奖励（维度洞察 / 永久微加成）**，与数字印记完全脱钩，不发放任何永久生产乘数。详见 `design/sprint5/gdd/numeral-persona.md` §2.3 与 `magnitude-milestone.md` §2.3。
4. **特殊成就联动已生效**：9 个档案成就（质数探索者/混沌行者/逆熵者/speedrun/marathon/centurion 等）随快照落库已可正常触发；Sprint 5 仅需补 UI 呈现与达成反馈。**Should**。
5. **Run 对比与目标挑战**：两张快照对比视图 + speedrun/marathon 内置目标（对应 Bartle Killer）。**Should**。
6. **档案导出/分享（轻社交）**：本地导出 JSON / 生成分享卡（无后端，纯本地）。**Could**。

### 2.4 对现有系统的牵动
- **存档结构**：`archives` 走 Dexie 独立表（ADR-002，**不膨胀主存档，已 live**）；`archiveUnlocked` 等已就位（`game.ts:1055` 附近），快照写入路径已接通，无需补。
- **Formatter**：档案数字展示复用现有 `format()`（含皮肤皮肤扩展），无需改造。
- **UI 主题**：`ArchiveModal` 复用 `--bg-primary` 等语义 CSS 变量（ADR-003 已统一），零侵入。
- **移动端布局**：卡片网格须响应式（对齐 `design/ux/mobile-layout-optimization*.md` 的间距下限与 `:deep` 收口规范）。

### 2.5 范围分层
- **Must**：① 快照采集+IndexedDB 持久化 ② ArchiveModal 基础 UI（网格+详情）③ 数字人格元升级最小闭环（1~2 档）。
- **Should**：④ 9 个特殊成就落地 ⑤ Run 对比 + speedrun/marathon 目标。
- **Could**：⑥ 档案导出/分享。

## 3. 方向 B：中期内容填补与知识纪元

### 3.1 一句话定位与核心动词
**定位**：在每个量级阈值（e10/e20/…）解锁"真实数学/物理知识"词条与小型里程碑奖励，给数字赋予意义、填补因子解锁后至首次超越前的中期空洞。
**核心动词**：**领悟（Comprehend） / 理解（Understand）**。

### 3.2 新增的核心循环
```
数字突破量级阈值 → 触发量级里程碑奖励（**非货币**：维度洞察 / 永久微加成，R1 已拍板权威口径）→ 解锁"知识点"词条（如 e23→阿伏伽德罗常数）
  → 词条自动收录进 Codex（复用 CodexSystem.onNarrativeTriggered 钩子）
  → 玩家在图鉴/知识点面板"看到这个数字在现实中意味着什么"
```
- 复用：`CodexSystem` 收纳、`EpochSystem` 阈值机制、`Formatter` 展示、`showNarration` 钩子。

### 3.3 关键系统拆解（4 个子系统）
1. **量级里程碑系统**：e10/e20/…/e300 每量级发放**一次性非货币奖励（维度洞察 / 永久微加成）**，与数字印记完全脱钩（R1 已拍板权威口径），不发放任何永久生产乘数。**Must**。
2. **知识点词条池**：~30~50 条真实数学/物理知识，按 log10 阈值解锁，正文 2~4 段。**Must**。
3. **Codex 知识分类**：在 `CodexCategory` 新增 `'knowledge'` 或并入 `origin`/`sage_record`，复用现有 UI。**Should**。
4. **中期事件密度提升**：在因子解锁后~首次超越前，提高事件/因子触发密度，缓解空洞。**Should/Could（需平衡测试）**。

### 3.4 对现有系统的牵动
- **存档结构**：新增 `unlockedMilestones: Set<number>`（量级）/ `unlockedKnowledge: Set<string>`（知识点），纳入 `Serializer`。
- **Formatter**：知识点数字示例复用现有格式化，无改造。
- **UI 主题 / 移动端**：复用 CodexModal 或新增轻面板，复用语义变量与移动端规范。

### 3.5 范围分层
- **Must**：① 量级里程碑 ② 知识点词条池（首批 ~20 条）+ 收纳。
- **Should**：③ Codex 知识分类 UI ④ 中期事件密度微调。
- **Could**：跨系统联动知识点（如某知识点解锁特殊维度叙事）。

> 评价：低风险、强正反馈、直接填中期空洞；但偏"内容补充"而非"系统结构性深化"，建议作为 **A 的 Should 层伴随内容**或独立短 Sprint。

## 4. 方向 C：维度精通深化与跨维度协同

### 4.1 一句话定位与核心动词
**定位**：闭环维度晶体消费出口（p0 缺陷 #7），把维度从"倍率切换"升华为"可养成的策略 build"，用跨维度协同增益制造策略深度。
**核心动词**：**主宰（Master） / 共鸣（Resonate）**。

### 4.2 新增的核心循环
```
维度资源积累（已在线 tickDimensionResources） → 合成维度晶体（已在线 synthesizeCrystal）
  → 维度晶体商店消费（NEW：购买跨维度增益 / 精通加速 / 维度羁绊）
  → 跨维度协同倍率（基于已精通维度组合）
  → 长期维度 build 养成
```
- 复用：`DimensionSystem`（资源/精通/晶体）、`MultiplierSystem`（注册 `'dimension'` 来源，已支持）、`SkinSystem` 主题解锁（已依赖维度精通）。

### 4.3 关键系统拆解（4 个子系统）
1. **维度晶体商店**：消费出口（全局加成/精通加速），闭环 p0 #7。**Must**。
2. **精通奖励实际化**：把 `DIMENSION_MASTERY_REWARDS` 文本变为真实被动加成。**Should**。
3. **跨维度协同增益**：已精通维度组合的羁绊倍率（策略深度，非线性通胀）。**Should**。
4. **维度挑战/精通里程碑**：基于精通度的长期目标。**Could**。

### 4.4 对现有系统的牵动
- **存档结构**：新增晶体消费记录/协同增益状态，纳入 `Serializer`；`dimensionCrystals` 已存在。
- **MultiplierSystem**：复用 `'dimension'` 来源注册，零架构新增。
- **UI 主题 / 移动端**：晶体商店集成进 `DimensionPanel.vue`（已存在），复用规范。

### 4.5 范围分层
- **Must**：① 维度晶体商店（消费出口）。
- **Should**：② 精通奖励实际化 ③ 跨维度协同增益。
- **Could**：④ 维度挑战里程碑。

> 评价：闭环已知缺口、复用度高、风险低；但增益仍以"倍率"为主，若不约束易与**抗通胀原则（支柱一）**轻微冲突——须以"策略多样性"而非"倍率堆叠"为设计目标。适合作为**收口型方向**，而非 Sprint 5 主方向。

## 6. 推荐结论与理由

### 6.1 推荐：以 **方向 A（档案馆与数字人格）** 为 Sprint 5 主方向，方向 B 作为 A 的 Should 层伴随内容

**理由（基于心流 / 留存 / 增量游戏长线健康）：**

1. **长线健康最优（抗通胀）**：A 的 meta 进度由"运行记录 + 解锁 + Run 多样性"驱动，而非更高数字，最契合 concept.md §7 的硬约束与支柱一"印记优先于通胀"。数字人格是"基于历史数据的身份"，天然抗通胀。
2. **复用资产最高、风险最低**：档案馆快照层已 **COMPLETE / ONLINE**（`captureRun`/`persistArchiveRecord` 全链路 live，`evaluateSpecialAchievements`/`computeSummary`/`archiveUnlocked` 已接通且生效），ADR-002（Dexie `archives` 独立表）已落地，`GeneSnapshot` 类型已定义。Sprint 5 是在已 live 的底层之上拓展"数字人格元升级 / Run 对比 / 档案分享"，是"叠加"而非"从零造"，契合"不重复造轮子"原则。
3. **强化转生动机（遗产感）**：v2.0 已有熵崩逼迫重置，但缺少"主动留下印记"的拉力。档案馆让 Transcend 成为"我的宇宙又进化了一轮"的仪式，**把重置从"惩罚规避"升级为"身份积累"**，直接提升留存与重玩意愿。
4. **心流与正反馈全覆盖**：A 提供长周期正反馈（档案里程碑/数字人格/特殊成就），与 B 的中周期量级/知识点、现有短周期购买/基因突变，共同构成短-中-长三层节奏，解决"挂机虚无"与"中期空洞"。
5. **覆盖全部 Bartle 类型**：Achiever（档案成就/数字人格）、Explorer（首次突破发现）、Killer（speedrun/marathon 目标）、Socializer（未来轻量分享/对比）。

### 6.2 为什么不单独主推 B 或 C
- **B** 低风险、强正反馈，但偏"内容补充"、结构深度有限；更适合作 A 的 Should 伴随（量级里程碑/知识点可直接接入档案馆"首次突破"发现），而非独占一个 Sprint。
- **C** 闭环了已知缺口（晶体消费），但增益仍以倍率为主，须额外约束才能不违背抗通胀原则；建议作为 A 完成后的**收口型 Sprint**或并行小迭代，而非 Sprint 5 主攻。

### 6.3 建议的 Sprint 5 范围（落地到 A + B 伴随）
- **Must**：档案馆快照采集+持久化、ArchiveModal 基础 UI、数字人格元升级最小闭环（1~2 档）。
- **Should**：9 个特殊成就落地、Run 对比 + speedrun/marathon 目标、**量级里程碑 + 首批知识点（B 的 Must）**。
- **Could**：档案导出/分享、知识点跨系统联动。

## 7. 风险与前置建议

| 风险 | 严重度 | 缓解 |
|------|:---:|------|
| IndexedDB `archives` 表迁移（Dexie 版本升级）可能丢旧档 | 中 | 先做 PoC 验证多表方案（架构评估 §6 已建议）；旧档无档案表时优雅降级 |
| 数字人格加成若设计不当仍会通胀 | 中 | 严格按"基于 Run 多样性/历史阈值的身份档位"，限定为少量全局倍率 + 叙事，禁止叠加倍率 |
| 质数检测大数字失效(#3)削弱质数维度策略 | 中 | Sprint 5 前置或并行修复，否则维度相关档案成就失真 |
| 维度晶体无消费出口(#7)遗留 | 低 | 可在 A 收尾后由 C 闭环，不阻塞 A |
| 移动端卡片网格布局 | 低 | 复用 `mobile-layout-optimization` 规范与 `:deep` 收口 |
