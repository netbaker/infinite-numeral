# 本地化评估（Localization Readiness）·《无限数域》

> 作者：路远行（release-polish）。结论：**本次发布仅 `zh-CN`，不阻塞**；i18n 尚未就绪，列入后续路线图。

---

## 1. 现状（接地气：基于真实代码扫描）

| 检查项 | 结果 |
|--------|------|
| i18n 框架（vue-i18n 等） | ❌ 未引入（`grep` 全仓无 `vue-i18n` / `createI18n`） |
| locale / 语言包目录 | ❌ 无（`src/` 下无 `locales` / `i18n` / `.json` 语言文件） |
| 硬编码中文字符串 | ⚠️ **约 9,619 处**中文字符串，分布于 **94 个** `.ts`/`.vue` 源文件 |
| 跨系统文案 | 成就名/描述、维度叙事、事件选项、图鉴词条、商店、引导、UI 标签——均为中文字面量 |

**i18n 就绪度：低（≈ 1/5）。** 当前为单一语言（简体中文）硬编码实现。

---

## 2. 影响评估

| 维度 | 影响 |
|------|------|
| 本次发布 | **无影响**。目标平台仅 Android、目标语言仅 zh-CN，本地化不阻塞发布。 |
| 未来多语言 | **高成本**。需抽取 ~9.6k 处中文字符串到语言包，并接入 i18n 运行时。 |
| 视觉负担 | **部分缓解**：游戏视觉以 emoji + CSS 为主（见 `docs/polish/visual-strategy.md`），图标类资源语言中立；但所有**文本**仍需翻译。 |
| RTL 语言（阿拉伯语等） | 当前布局为 LTR；若未来做阿拉伯语需额外 RTL 适配（不在本次范围）。 |

---

## 3. i18n 路线图（建议，非本次交付）

> 阶段划分，供 LEAD 排期；与"静音发布""视觉 P0 债"同为 fast-follow 候选。

### 阶段 L1 · 框架接入与基线抽取（前置）
- 引入 `vue-i18n`（与 Vue3 + Pinia 兼容）。
- 建立 `src/locales/zh-CN.json` 作为基线语言包。
- 接入 `Formatter` / 数字皮肤等已有文本出口，统一走 i18n。

### 阶段 L2 · 字符串冻结与抽取
- **字符串冻结**：冻结 UI 文案（新功能先建 key，不内联中文）。
- 逐步将 ~9.6k 处硬编码中文迁移为 `t('key')` 调用。
- 优先级：核心循环 / 设置 / 引导 > 叙事文案 > 彩蛋。

### 阶段 L3 · 首语言扩展（en-US）
- 新增 `src/locales/en-US.json`，完成英文翻译。
- 语言切换 UI（设置内）+ 跟随系统语言。
- 验证：长文本换行、数字格式（千分位/科学记数法本地化）。

### 阶段 L4 · 多语言扩展（可选）
- `ja-JP` / `ko-KR` 等；按需。
- 若涉及 RTL（ar），补充 RTL 布局适配。

## 5. 给文案/设计的提示
- 新增叙事/成就/维度文案时，**先定义 i18n key**，即便当前仅中文，也为未来抽取减负。
- 避免在代码逻辑里拼接中文句子（如 `数量 + "个"`），改为带占位符的模板 `t('x.count', { n })`，便于本地化与单复数。
